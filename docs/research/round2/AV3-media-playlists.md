# AV3: Adversarial verification of audit sections 3.3 (media) and 3.4 (playlists)

Target: `docs/yodeck-workflow-audit.md` sections 3.3 and 3.4 (lines 170 to 240). Checked on 2026-11-03 against the full local text of the Yodeck help centre (`scratchpad/web/art/*.txt`, 656 articles) and the public OpenAPI spec `scratchpad/web/probe-api-docs_bundle.yaml` ("Yodeck API - Beta", version 2.0.0, fetched 2026-11-03 from https://app.yodeck.com/api-docs/bundle.yaml). No WebSearch calls were used. No repository files were edited.

HELP = https://help.yodeck.com/en/articles/ . SPEC = https://app.yodeck.com/api-docs/bundle.yaml (line numbers refer to the local copy). For "UPDATED", "this week" is the help centre's relative label as scraped on 2026-11-03 (it means late October or early November 2026).

## Summary

- 54 claims checked (one table row each): **33 CONFIRMED**, **14 CORRECTED**, **3 REFUTED**, **4 STILL UNKNOWN**. Row 11 counts as REFUTED within the corpus.
- Several claims the audit marked THIRD PARTY are stated in Yodeck's own OpenAPI spec, so they move to VERIFIED_FULL_PAGE: the media status lifecycle, the pre-signed upload and complete flow, the availability fields and weekday string, playlist item types, sub-playlist `max_items` and `max_time`, the 23 named transition types, and the missing workspace filter on the playlists list.
- Corrections that matter for the TINNOX spec:
  1. **Availability datetimes.** The spec says the timestamps carry no time zone and are "interpreted based on the screen's location". This settles the conflict the audit reported, apart from one quirk: the spec's own examples end in `Z`.
  2. **Weekdays are a 7-character binary string** with Monday first (`"0101011"`), not an integer bitmask.
  3. **Tag-based playlist ordering is alphabetical by default.** `shuffle_content` defaults to false, which gives alphabetical order. The forum claim about upload order is refuted.
  4. **Transitions.** There are 23 named types plus `random`. The audit's figure of "about 25" comes from the help page.
  5. **Re-encoding.** Three official pages say all uploads are re-encoded. The "repackaged in about 30 seconds" release note does not appear in the corpus.
  6. **Nesting.** It is now documented. A sub-playlist can contain another one, and Yodeck advises keeping nesting to one level.
  7. **No "Repeat Items" field in the API.** The spec's `subplaylist` item has `max_time` and `max_items` only.
  8. **The "200-slide cap" and "all media play at least once" do not appear** in any full page.
- Yodeck's own documentation contradicts itself in two places. The audit already notes both:
  - images: "not resized" in the manual, against "cropped above native resolution" in the LG webOS troubleshooting guide;
  - video: "all files re-encoded", against the per-upload skip-encoding option.
