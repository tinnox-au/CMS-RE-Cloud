Evidence: the full local text of 656 Yodeck help-centre articles (`scratchpad/web/art/*.txt`) and the Yodeck public OpenAPI spec v2.0.0 (`scratchpad/web/probe-api-docs_bundle.yaml`, fetched today from https://app.yodeck.com/api-docs/bundle.yaml). WebSearch calls used: 0. No Yodeck UI observed.
Abbreviations: HELP = https://help.yodeck.com/en/articles/ ; SPEC = the OpenAPI bundle (line numbers as in the local file). "UPDATED" is the article's own header line as scraped today.

## Summary

- **61 claims checked (29 layout/LED, 32 scheduling/time zone): 42 confirmed, 12 corrected, 1 refuted, 6 still unknown.** S29 is counted as confirmed for the API part; its UI part is still unknown.
- **The keyword sweep: DST is still undocumented.** Across all 656 articles and the spec, "daylight", "DST" and "summer time" each return **0 hits**. Australian zones do exist, though. The spec's screen `time_zone`/`time_subzone` enum lists **23 Australia subzones**, including `Melbourne`, `Lord_Howe`, `LHI` and `Eucla` (SPEC 9555-9600, repeated at 11064 and 13082). The Date & Time app source lists 23 IANA `Australia/*` names and uses moment-timezone with its bundled data (HELP 456347).
- **The audit's statement "No Australian zone value was observed anywhere" is REFUTED.**
- **The API time-zone format, which the audit marked "UNVERIFIED", is now VERIFIED.** A screen stores the zone as two strings, `time_zone` (continent, e.g. `Australia`) and `time_subzone` (city, e.g. `Melbourne`). They default to `Etc` / `UTC` (SPEC 9117-9160, 9866). Schedule event `start`/`end` and media availability timestamps carry **no offset**, and the screen's location sets how they are read (SPEC 6009, 7351-7359). Event times are therefore naive local wall-clock times. Nothing says how a time that falls in the missing or repeated DST hour is handled.
- **The UTC offsets in the spec's zone labels are DST-season values, not standard offsets.** The labels read Melbourne (UTC+11), Lord Howe (UTC+11), Adelaide (UTC+10:30), New York (UTC-4), London (UTC+0) and Auckland (UTC+13). That pattern only holds between late October and early November, so the labels were most likely generated at build time from a DST-aware zone database (INFERRED). A TINNOX operator reading "Melbourne UTC+11" in winter would be misled. TINNOX should not copy labels with fixed offsets.
- **Six notable corrections:**
  - "After N occurrences" is an official repeat option, not third-party only.
  - A "Turn Screen Off" event type is official.
  - The recurring-event exception UI (This event / This and future / All) is official.
  - The Pi 5 limit is "limited performance with more than one dynamic zone", not "no multi-zone".
  - Magic Layout is "free for all Yodeck users at launch", so its tier is no longer unknown.
  - 180-degree ("upside-down") orientation is mentioned in an official video-wall article, not only by a third party.
- **New contradictions inside Yodeck's own pages:**
  - Android: the Basic Info article lists a Timezone field, but Android Limitations says the time zone "can't be set from Yodeck yet".
  - Resume after an interruption: Schedules Introduction says playback restarts from item 1, while Prioritization Scenario 2 says the promo "resumes".
  - Ticker direction: one page says "right to left"; the same page says the default direction is "Left to Right".
