### Logout and session handling

**UTX-01.** I ran the first-parent and PR implementations with the same 1,856-character synthetic ID-token hint. The first produced a 1,995-character URL that `LogoutResponseSchema` accepted. The PR produced a 2,012-character URL that it rejected. The API accepts stored hints up to 8,192 characters, revokes the CMS session, and returns the URL. The portal validates that response before calling `location.assign`, so Keycloak never receives the logout request in this case. Align the response contract with the supported hint and endpoint sizes, and test the generated URL through the portal parser at the boundary. ### Uploads and accessibility

Each reload starts with a null poll interval, and this library supplies a polling *function* whose interval is established only after a successful read.
