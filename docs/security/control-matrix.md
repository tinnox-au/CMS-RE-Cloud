# Security control matrix: TINNOX CMS prototype M0

Date: 2026-11-14. Companion to `docs/security/threat-model.md` (threat numbers T1 to T16) and `docs/prototype-m0.md` (decisions D1 to D19).

## How to read this page

- **Implementation in M0** describes the control as built. The first version of this page was written against the design while the code was being built; the integration step (2026-11-14) checked each row against the code and corrected it where the build differs.
- **Evidence** gives a status and where it comes from. `TESTED` means an automated test that ran and passed on 2026-11-14 exercises the control (the final re-run after the review fixes is recorded in `docs/prototype-validation.md` section 10); the test file is named, and the run and its counts are in `docs/prototype-validation.md`. `IMPLEMENTED` means the code exists and was read, but no test proves it. `PARTIAL` and `NOT DONE` say what is missing. File names are relative to the repository root; `e2e/…` is `tests/e2e/…`, `integration/…` is `tests/integration/…`.
- This matrix maps controls to published guidance. **It is not a compliance statement.** The prototype is not certified, not IRAP assessed, not at any Essential Eight maturity level, and not assessed against the Privacy Act. Which obligations apply to TINNOX is for TINNOX and its advisers to determine (section 6).

Three kinds of responsibility are kept apart throughout:

- **(a) Engineering controls**: sections 1 to 4.
- **(b) Organisational responsibilities TINNOX must own**: section 5.
- **(c) Legal applicability TINNOX must determine with counsel**: section 6.

## 6. Legal applicability TINNOX must determine with counsel

This page states no legal conclusion. The OAIC guidance read for this milestone is summarised only to frame the questions.

1. **Whether the Privacy Act 1988 and the Australian Privacy Principles apply to TINNOX**, in whole or for particular activities. OAIC's small-business page describes a turnover threshold of $3 million and a list of businesses covered regardless of turnover (for example those related to a covered business, Commonwealth contracted service providers, and those that have opted in). TINNOX must apply that test to its own facts.
2. **Whether the Notifiable Data Breaches scheme applies**, which OAIC describes as following from APP 11 obligations.
3. **TINNOX's role for customer data**: what personal information the CMS would hold (operator accounts, audit records, any people shown in customer media), and for whom.
4. **APP 8** if any personal information would be disclosed to an overseas recipient, including through a provider. OAIC's chapter 8 distinguishes "disclosure" from "use" and discusses when storage with an overseas cloud provider may be a use; it frames an accountability mechanism for cross-border disclosure. It is not a rule that all data must be stored in Australia. TINNOX's Australian-hosting preference is a product requirement (D18; operations checklist section 4), separate from this legal question.
5. **Customer contractual obligations** and any **sector- or state-specific requirements** (for example government or health customers).
6. **Retention obligations** under any other law that applies to TINNOX's records.
